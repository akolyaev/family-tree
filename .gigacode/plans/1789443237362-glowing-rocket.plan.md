### Шаг 2: JPA Entity `Person`

**Файл:** `src/main/java/com/akolyaev/family_tree/domain/Person.java`

**Пакет:** `com.akolyaev.family_tree.domain`

**Ключевые паттерны:**
- `@Entity @Table(name = "person")`
- Lombok: `@Getter @Setter @NoArgsConstructor @AllArgsConstructor @Builder`
- Поля с `@Column(name = "...")` — маппинг camelCase → snake_case
- `@ManyToOne(fetch = FetchType.LAZY)` для father, mother, spouse
- `@JsonBackReference` на father/mother/spouse для предотвращения циклической сериализации
- `LocalDate` для birthDate, deathDate
- `Boolean` (wrapper) для isClaimed

**Поля:**
```
id (Long), firstName, lastName, bio, photoUrl, birthDate, deathDate,
ownerUsername, isClaimed, father (Person), mother (Person), spouse (Person)
```

### Шаг 3: DTO классы

**Файлы:**
1. `src/main/java/com/akolyaev/family_tree/dto/PersonRequest.java`
2. `src/main/java/com/akolyaev/family_tree/dto/PersonResponse.java`
3. `src/main/java/com/akolyaev/family_tree/dto/TreeResponse.java`

**Пакет:** `com.akolyaev.family_tree.dto`

**PersonRequest** — для CREATE/UPDATE:
```
firstName, lastName, bio, photoUrl, birthDate, deathDate,
ownerUsername, fatherId (Long), motherId (Long), spouseId (Long)
```
- Без `id` (автоинкремент)
- Без `isClaimed` (управляется через claim endpoint)
- Lombok: `@Getter @Setter @NoArgsConstructor @AllArgsConstructor @Builder`

**PersonResponse** — для отображения:
```
id, firstName, lastName, bio, photoUrl, birthDate, deathDate,
ownerUsername, isClaimed, fatherId (String), motherId (String), spouseId (String)
```
- `fatherId/motherId/spouseId` — `String` (значение ID, а не вложенный объект)
- Lombok: `@Getter @Setter @NoArgsConstructor @AllArgsConstructor @Builder`

**TreeResponse** — структура семейного графа:
```
root (PersonResponse), wife (PersonResponse), children (List<PersonResponse>)
```
- Lombok: `@Getter @Setter @NoArgsConstructor @AllArgsConstructor @Builder`

### Шаг 5: PermissionService

**Файл:** `src/main/java/com/akolyaev/family_tree/service/PermissionService.java`

**Пакет:** `com.akolyaev.family_tree.service`

```java
@Service
public class PermissionService {
    boolean isOwner(Person person, String username);
    boolean canEdit(Long personId, String currentUsername);
}
```

**Логика:**
- `isOwner`: `person != null && person.getOwnerUsername() != null && person.getOwnerUsername().equals(username)`
- `canEdit`: ищет person по ID, вызывает `isOwner`

### Шаг 6: PersonService (Tree Logic + CRUD)

**Файл:** `src/main/java/com/akolyaev/family_tree/service/PersonService.java`

**Пакет:** `com.akolyaev.family_tree.service`

**Методы:**

| Метод | Описание |
|-------|----------|
| `create(PersonRequest)` | Создаёт person, устанавливает father/mother/spouse по ID, сохраняет |
| `getById(Long)` | Возвращает `PersonResponse` по ID |
| `findAll()` | Возвращает `List<PersonResponse>` |
| `update(Long, PersonRequest)` | Обновляет поля person, сохраняет |
| `delete(Long)` | Удаляет по ID |
| `getFamilyTree(String rootUsername)` | Возвращает `TreeResponse` с root, wife, children |
| `updatePhotoUrl(Long, String)` | Обновляет photoUrl (stub) |
| `claimPerson(Long, String)` | Устанавливает ownerUsername + isClaimed=true |

**Логика `getFamilyTree()`:**
1. Находит root по `ownerUsername`
2. Находит wife через `root.getSpouse()` (через spouse_id)
3. Находит children: фильтрует всех, где `father.id == root.id || mother.id == root.id`
4. Собирает `TreeResponse`

**Важно:** `toResponse(Person)` — маппинг entity → DTO. Извлекает scalar fields + ID родителей/супруга как String.

## Потенциальные проблемы

1. **Циклическая JSON сериализация** — `@JsonBackReference` на father/mother/spouse в entity
2. **H2 vs PostgreSQL** — `columnDefinition = "TEXT"` может вести себя по-разному в H2. Если проблема — убрать columnDefinition
3. **N+1 queries** — `findChildren()` делает `findAll()` и фильтрует в памяти. Для MVP ок, для масштаба — нужен `@Query`
